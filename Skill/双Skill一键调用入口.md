## 二、首次配置：在新环境中完成一次即可

1. **加载本文件**，将其作为双 Skill 的总调用入口。
2. 加载导演 Skill 主文件，保留其自己的模式路由与 references 规则；不要一次性无差别导入所有导演参考文件。
3. 加载提示词生成 Skill V10.21 主文件，并将其设为提示词生成的唯一当前主版本。历史版本只作查阅，不作为默认入口。
4. 让提示词 Skill 能访问「提示词知识库」总索引及其相关分类。正式生成提示词时，先扫描总索引，再按 V10.21 规则判断并检索所有相关分类与依赖链。
5. 外部 MiniMax Skill 只作参考资料。吸收方法前先对照 V10.21；已有能力不重复堆叠，新增内容只补缺口。
6. 完成后用下方「快速调用指令」测试：先试纯提示词任务，再试导演+提示词的完整链路。

若平台支持将 Markdown 文件注册为 Skill，请将本文件注册为入口 Skill，并把两套主 Skill 作为独立子 Skill/知识文件保留；若平台只支持单文件上下文，则上传本入口文件后，再按任务路由加载对应主文件和必要参考资料。

## 三、每次任务的自动路由规则

收到用户请求后，先判断任务属于哪种类型，不要默认每次都跑完整制作流程。

### 路由 A：只做导演工作

适用：开发故事、优化剧情、人物弧光、对白潜台词、场景冲突、节拍表、Blocking、镜头清单、分镜方案、制作计划、剪辑结构、连续性诊断、失败原因诊断。

执行：
1. 读取导演 Skill 主文件。
2. 按主文件的 Routing 表选模式 A–J。
3. 只加载该任务要求的 references/templates；大型参考文件按索引只读相关章节。
4. 交付导演层产物，不自动把它改写成提示词，除非用户也要求提示词。

### 路由 B：只做提示词生成

适用：用户已经说清楚画面，只要求“写提示词”“生成 MiniMax 提示词”“复刻镜头提示词”等。

执行：
1. 读取 Reality Cinematic Engine V10.21 主文件。
2. 读取提示词知识库总索引，扫描全部一级分类；根据场景触发条件检索相关分类、子集与跨分类依赖。
3. 按 V10.21 原流程完成写前分析、摄影机路线、时间锚点和质量自检。
4. 严格使用 V10.21 固定输出模板、字段顺序与末尾顺序。
5. 用户只要提示词时，只交付提示词本身，不附加分析说明。

### 路由 C：导演 + 提示词完整链路

适用：用户说“从编剧导演角度完整设计并生成提示词”“帮我把故事打磨后做成可生成的短剧镜头”“从创意到最终视频提示词全流程完成”等。

严格按以下顺序：

1. **导演阶段**：读取导演 Skill；必要时读取故事开发补充模块；确定人物目标、冲突、场景转折、可见动作、表演策略、镜头意图与空间调度。
2. **交接冻结**：把已确定的信息整理为交接包（见第四节），区分用户已指定事实与导演提出的建议；用户明确给出的设定不得被擅自覆盖。
3. **提示词阶段**：读取 V10.21 与提示词知识库总索引；依据交接包检索相关视觉知识库；将导演意图转译成可执行生成描述。
4. **提示词 QC**：检查时长、动作预算、动作起始/变化/结束状态、人物连续性、站位/视线/轴线、镜头运动动机、对白可说完程度、口型与声音层次、光线与材质一致性、色卡和负面约束。
5. **交付**：导演方案和提示词可分别输出；如果用户只要最终提示词，内部完成导演阶段，但最终仅按 V10.21 模板输出。不得把导演 Skill 的模板塞进提示词 Skill 模板。

## 四、导演 → 提示词的标准交接包

交接包是两套 Skill 之间的内部桥梁，不替代任何一套原模板：

- 项目/场景目标：
- 用户锁定的事实（不得改动）：
- 人物身份与关系：
- 人物当前目标、阻力与潜台词：
- 本段戏剧变化（开始状态 → 转折 → 结束状态）：
- 可见动作与表演变化链：
- 场景空间、人物站位、视线与轴线：
- 镜头意图与切镜理由：
- 目标时长及关键时间锚点：
- 对白原文、说话人、语气、停顿：
- 环境声/动作声/音乐要求：
- 视觉基调、光线、色彩与材质方向：
- 必须保持的连续性：
- 不能出现的内容：
- 尚未确定、需要保留弹性的部分：

交接规则：
1. 用户明确提供的内容优先级最高。
2. 导演阶段可以提出创作建议，但不能把建议伪装成用户已经确定的事实。
3. 如果关键创作信息并非生成所必需，不要为了填满交接包而追问；采用合理且不冲突的默认值。
4. 用户只要求一个短镜头时，导演阶段应轻量化，不要强行展开整季结构或完整制作圣经。

## 五、不可违反的双 Skill 边界与保护规则

1. **两套 Skill 永远分开**：导演 Skill 负责故事、表演、调度和制作决策；提示词 Skill 负责把已确定意图转换为模型可执行提示词。
2. **不合并主文件、不互相覆盖、不复制整套模板。**
3. **V10.21 原模板与流程冻结**：不得删除字段、改字段顺序、改末尾固定顺序或另造替代模板。除非用户明确授权修改，否则只能增量完善。
4. 提示词 Skill 的固定末尾顺序必须保持：皮肤质感 → 画面质感（光感并入）→ 负面词。
5. 提示词生成不能跳过知识库总索引扫描；需要相关知识时按依赖链检索，不能只凭关键词命中一个文件就声称完成全库检索。
6. 不要把外部 MiniMax H3 的专属字段、时长/帧率/素材限制强行套用到其他 MiniMax/Hailuo 模型。先确认具体模型与工作模式；未知时不要声称已做模型专属校验。
7. 不能实际读取的链接、未安装的 Skill、未执行的校验器，必须如实说明；不得声称已调用或已验证。
8. 参考文件只按任务加载必要部分，避免无差别塞入所有内容造成上下文稀释。
9. 用户要求“只输出提示词”时，最终响应不得附加本文件的流程说明。
10. 若导演方案与用户锁定的角色、事件、参考素材或既有世界观冲突，保留用户设定，并只修复冲突部分。

## 六、快速调用指令（可直接复制到任何新聊天）

### 1. 只生成提示词

“请先读取《双 Skill 一键调用入口文件》，按路由 B 调用 Reality Cinematic Engine V10.21，并读取 GitHub 提示词知识库总索引与所有相关分类。严格保留 V10.21 原模板、字段顺序和末尾顺序。任务：{在此填写画面、时长、风格、对白及其他要求}。最终只输出完整提示词。”

### 2. 先导演设计，再生成提示词

“请先读取《双 Skill 一键调用入口文件》，按路由 C 串联导演 Skill 与 Reality Cinematic Engine V10.21。先完成必要的导演分析与场景调度，再建立交接包，然后由 V10.21 检索提示词知识库并按原模板生成最终提示词。两套 Skill 不合并、不覆盖；用户锁定的设定不可擅自更改。任务：{在此填写需求}。最终交付：{导演方案+提示词 / 只要提示词}。”

### 3. 只做导演/编剧工作

“请先读取《双 Skill 一键调用入口文件》，按路由 A 调用导演 Skill，按其模式路由只加载必要参考资料。不要启动提示词生成 Skill，除非我明确要求。任务：{在此填写故事、人物、场景或分镜需求}。”

### 4. 检查或修复现有提示词

“请先读取《双 Skill 一键调用入口文件》，先判断问题属于故事/调度问题还是提示词执行问题。前者使用导演 Skill 对应模式；后者使用 Reality Cinematic Engine V10.21 与相关知识库。只有我要求完整修复链路时才串联两套 Skill。保留用户锁定内容与 V10.21 原模板。”

## 七、每次执行后的简短自检

- [ ] 是否加载了对应主 Skill，而非误用历史版本？
- [ ] 是否保持两套 Skill 分离？
- [ ] 若生成提示词，是否读取知识库总索引并按需检索相关分类？
- [ ] 是否遵守 V10.21 固定模板与末尾顺序？
- [ ] 是否把动作、时间、镜头、对白和声音写成可执行约束？
- [ ] 是否避免把 H3 专属规则误套到其他模型？
- [ ] 是否如实说明未能读取或未实际验证的内容？
- [ ] 最终输出是否严格符合用户要求？
