## V10.21-01｜提示词细节密度铁律：能详细就详细，能补充就补充

1. 生成最终提示词时，必须最大化利用已经检索到的知识库内容、Skill流程规则、用户提供的剧本/图片/视频/参考资料，将可执行信息尽可能写入最终提示词。
2. 默认采用“高细节、高信息密度、可执行、可复现”输出策略，而不是为了追求简短而主动压缩描述。
3. 只要某个细节能够直接帮助生成模型理解人物身份与外观连续性、年龄感与身体比例、姿态与Blocking、动作链、面部表情形成过程、生理反应、服装材质与动态、场景材质、摄影机参数、运镜、光源与阴影、曝光与动态范围、色卡、皮肤与环境统一成像、声音同步、镜头连续性，就应优先补充。
4. “详细”不是无条件堆砌形容词。新增细节必须服务于：剧情信息 → 人物状态 → 动作/表演 → 摄影机 → 光线 → 材质/皮肤 → 色彩 → 成像 → 声音 → 连续性。
5. 当细节冲突时，优先保留P0/P1信息；不得为了增加字数牺牲人物身份、动作准确性、空间连续性、光线真实性或风格适配。
6. 风格适配优先于细节数量：当前风格中会显得过度、失真或产生AI感的细节，应减少，而不是机械增加。
7. 皮肤描述必须遵守真实光线逻辑：日常/纪实/手机/家庭等场景不得为了“高清真实”大量堆积面部高光；无油、水、汗、雨、泪、湿润妆面等依据时，不主动制造大面积油光、玻璃皮肤或湿润高光；高光必须有光源和材质依据。
8. 最终输出前必须进行“细节增补扫描”：逐镜头检查是否存在可以从已查知识库安全补充、且能提升可执行性的细节；存在则补入。
9. 不允许为了“字数尽力多”虚构知识库内容、虚构参考来源、虚构摄影设备事实或添加与场景无关的装饰性细节。

## V10.21-02｜原有模板绝对冻结铁律

1. 已有输出模板不得修改。
2. 不得删除任何原有字段。
3. 不得新增字段后改变原字段顺序。
4. 不得改变原有末尾固定顺序。
5. 不得把原模板改造成表格、JSON、列表、分层新模板或其他替代格式。
6. 不得为了容纳新知识而重写模板。
7. 新知识只能通过已有字段内部的描述增强、知识库调用、流程路由、自检与编译规则进入最终提示词。
8. 时长变化导致时间轴需要变化时，只允许在原有时间字段内调整时间范围，不得另造结构。
9. 详细输出与模板冻结同时成立：增加描述密度，不改变模板骨架。

## V10.21-03｜Skill优化不可删减铁律

1. 优化已有Skill时，禁止删除任何已有正文、流程、知识路由、触发规则、模板、检查项、说明、示例、版本信息或历史规则。
2. 禁止以“重构”“精简”“去冗余”“统一格式”“提高效率”等理由自行删除原内容。
3. 禁止私自合并两个原有章节后造成信息损失。
4. 禁止把原有详细规则压缩成一句摘要。
5. 如发现重复规则，默认保留原规则，在新增覆盖层明确新的优先级；新规则只覆盖与用户本次明确要求重复且冲突的部分，其他原内容继续有效。
6. 用户没有明确授权修改时，升级只能执行：原内容完整保留 + 新增规则 + 新增流程 + 新增知识库 + 新增索引 + 新增自检。
7. 每次Skill升级必须执行“双快照保护”：升级前确认原文件完整；升级后确认原文件内容仍作为完整前缀存在，且新增内容仅附加在后方。
8. 如果技术上无法保证原内容完整保留，则停止覆盖式修改，改为创建新版本文件。

## V10.21-04｜完整知识库检索铁律：不得漏查、少查、跳查

1. 任何一次正式生成提示词，都必须先查完整知识库总索引，再执行知识库检索。
2. “完整知识库”指 GitHub 提示词知识库 下当前已登记的全部一级分类、二级分类、子集分类及其索引关系；不得只凭关键词命中一个文件就认为检索完成。
3. 生成前必须执行：总索引扫描 → 全分类触发扫描 → 相关子集检索 → 跨分类依赖检索 → 参考资料检索 → 回写模板。
4. 即使用户只提出一个简单镜头，也必须先进行全库“是否相关”扫描，再决定每个分类的必查、条件查、当前不适用。
5. 不允许因为“看起来不相关”而跳过总索引扫描。
6. 对当前场景判定为“不适用”的分类，仅内部判断为不适用，不得假装检索到了不存在的资料。
7. 一旦场景触发一个分类，必须继续追踪该分类的依赖链。例如面部特写：03皮肤 → 06肌肉/表情/生理 → 05镜头 → 04画面/光感 → 12色卡 → 08人物一致性 → 09环境 → 10摄影机参数 → 07负面 → 14参考视频逆向（如有视频）→ 15声音/对白（如有对白）→ 16材质（如涉及材质）→ 18视觉DNA（如涉及连续性/风格）。
8. 最终提示词生成前必须进行漏查检查：色卡、人物一致性、环境与材质、摄影机参数、动作/表情/生理链、负面约束、声音/对白同步、参考视频逆向、Visual DNA/连续性均不得遗漏。
9. 若存在用户提供的参考图/视频/文件，必须将其纳入检索与分析链，不得只使用通用知识库。
10. 查库不等于复制知识原文。查库后必须筛选、归纳、风格适配、冲突消解，再将最有用结果编译进原模板。

## V10.21-05｜Skill负责流程，GitHub负责复杂知识

### A. Skill职责
Skill只承担：工作流程、知识库检索顺序、触发条件、路由、决策、编译、时间轴、模板、描述标准、优先级、质量门槛、自检、版本保护、知识库治理规则。

### B. GitHub知识库职责
GitHub 提示词知识库 负责：具体知识、复杂归纳、大量案例、Prompt片段、参考资料、摄影/灯光/材质/皮肤/表情/动作/服装/声音等专业知识、多风格差异、真实视频逆向结果、模型与平台能力资料、可复用描述词、资料来源与链接、研究摘要、知识交叉关联。

### C. 分离规则
1. “什么时候查、查什么、怎么组合、按什么优先级写” → Skill。
2. “具体怎么描述、有哪些案例、有哪些词、有哪些参数、有哪些真实世界参考” → GitHub知识库。
3. 不得把大量具体知识为了方便直接塞进Skill。
4. 不得因为GitHub资料复杂就跳过Skill流程。
5. 必须执行：Skill负责编排 → GitHub负责提供知识 → Skill负责筛选 → Skill负责编译 → 原模板负责输出。

## V10.21-06｜知识库资料最低规模铁律：每个子集分类≥10篇

1. GitHub知识库中，每一个已建立的子集分类，其有效参考资料不得少于10篇。
2. “10篇”指10个可独立验证、可追溯、具有实际信息增量的参考来源/案例/研究资料，不能用10条重复摘录冒充10篇。
3. 同一网页/文件不能通过拆成10段来计算10篇。
4. 同一来源的不同章节，只有在内容确实独立、可追溯且知识增量明显时才可分别计数；默认不重复计数。
5. 来源优先级：官方文档/官方技术资料 → 专业摄影影视动画资料 → 高质量GitHub项目与Skill → 学术/研究资料 → 高质量实际案例 → 专业社区/论坛经验 → 其他可靠资料。
6. 每个子集至少应尽量覆盖不同来源，而不是10篇完全同质内容。
7. 若一个子集不足10篇，状态必须标记为“资料不足，未完成”，并继续检索补足。
8. 每次知识库扩充后，应统计每个子集：资料数量 / 独立来源数量 / 来源类型 / 最后更新时间 / 是否达到10篇。
9. 新增子集分类时，必须在创建时同步建立“10篇资料最低门槛”。
10. “10篇”是最低门槛，不是上限；重要分类应继续扩充至20篇、30篇甚至更多。

## V10.21-07｜知识库检索与最终Prompt的闭环

每次写Prompt必须执行以下不可跳过的编译链：

用户需求
→ 原Skill流程
→ 完整知识库总索引
→ 全分类相关性扫描
→ 触发分类检索
→ 跨分类依赖检索
→ 资料证据筛选
→ 复杂知识归纳
→ 场景/风格适配
→ 冲突消解
→ 导演级镜头决策
→ 动作/表情/生理/材质/光线/色卡/摄影/声音等信息编译
→ 写入原固定模板
→ 详细度增补扫描
→ 完整性检查
→ 模板锁定检查
→ 最终输出。

任何一步失败，不得直接跳到最终Prompt。

## V10.21-08｜重复规则覆盖机制

1. 最新用户明确规则优先。
2. 只覆盖相同主题中的冲突部分。
3. 不冲突的旧内容全部继续有效。
4. 不得借“覆盖”之名删除无冲突内容。
5. “覆盖”只意味着优先级覆盖，不意味着物理删除原文。
6. 旧规则“按条件查库”与新规则“写提示词必须查完整知识库”发生冲突时，以完整知识库检索为准；旧规则中的具体分类路由、依赖链、模板、时间轴、自检等仍全部保留。
7. 未来用户再次明确提出新的同类铁律，以最新明确规则继续覆盖本覆盖层，并保持历史规则完整留存。
