# GitHub方法论：Prompt结构与时间轴强化

## 核心结构
主体/人物 → 场景 → 起始状态 → 情绪起点 → 变化链 → 动作链 → 台词/声音 → 镜头 → 运镜 → 光线 → 色彩 → 成像 → 皮肤 → 环境材质 → 时间锚点 → 约束。

> 这是知识层结构，不覆盖主Skill现有标准输出模板。

## 时间轴原则
- 先确定“本段真正发生什么”，再决定分几段。
- 每段至少有明确的起始状态、动作/变化、结束状态。
- 关键动作与台词字词绑定；不要把无法在指定秒数完成的动作堆在同一段。
- 8秒以内优先保持一个清晰主事件；超过8秒才根据复杂度增加时间分段。
- 快速插入镜头如果无法单独承担完整语义，可并入相邻节拍。
- 镜头数量服从时长，不为了“电影感”强行切镜。

## 可见化转换
抽象词必须转换成可观察证据：
- “紧张” → 呼吸变浅、停顿、手指收紧、视线短暂回避。
- “疲惫” → 眼睑沉、动作减速、肩部下沉、呼吸节奏变化。
- “怀疑” → 目光停留、眉间轻收、身体保持距离。
不要只写抽象情绪标签。

## 多镜头冲突控制
- 同一时间段只设置一个主要摄影机运动。
- 不同时写“固定镜头”和“摄影机环绕”。
- Pan/Tilt/Zoom 与 Dolly/Truck/Tracking/Crane 区分：前者主要是镜头方向/焦距变化，后者是摄影机空间位移。
- 任何参考视频引用必须说明“参考动作/运镜/节奏/光线/构图中的哪一项”。

## Prompt QC
生成前检查：
1. 主体是谁？
2. 主动作是什么？
3. 起始状态是什么？
4. 结束状态是什么？
5. 动作能否在时长内完成？
6. 镜头是否服务动作/信息？
7. 光源是否有现实依据？
8. 皮肤/材质是否与环境成像一致？
9. 是否存在互相冲突的指令？
10. 是否把推测写成了参考视频中“已经观察到”的事实？
